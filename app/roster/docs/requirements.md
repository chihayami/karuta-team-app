# App固有仕様

業務要件と具体的な設計案を記載する. 未確定の判断は「案」または「未決」と明示する.


## 名簿管理

要件:

- 指定の名簿管理者が会員登録・編集・休退会・昇級・履歴確認・取込出力を行う.
- 名簿管理者はSUPER_ADMINとは別の役割とする.
- 昇級登録は名簿管理者より広い担当者に許可する可能性があるため, 独立して付与できる権限・ロールにする.

提案する権限分割:

| 権限 | 内容 | 付与先案 |
| --- | --- | --- |
| roster.read / roster.write | 名簿参照・登録・編集・休退会 | 名簿管理者 |
| roster.import / roster.export | 一括取込・出力 | 名簿管理者 |
| roster.history.read | 会員の状態・級等の業務履歴の参照. 操作履歴の専用画面は初回対象外 | 名簿管理者 |
| promotion.register | 昇級登録と必要最小限の対象会員参照 | 名簿管理者, 昇級登録担当 |

一般編集による級の変更も昇級権限の検証を通す案とする. API・一括取込から権限を迂回できないことを検証する.
誰がいつ何を変更したかを履歴に残し, 取込時は会員コードの重複・必須項目・級等を検証する案とする.
名簿変更は名簿管理者からのみ行う. 変更申請は初回・将来とも本アプリのスコープ外とし, 公式アカウント等の別チャンネルで申告する. 昇級専用担当による昇級登録は例外として維持するとする.
