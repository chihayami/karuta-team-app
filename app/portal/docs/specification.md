# ポータル仕様案

[SCR-PTL-01](screens-and-flows.md#scr-ptl-01)を所有. 認証Appから主体と利用可能な対象会員を取得し, 各Appへの入口を表示する. 各Appの権限確認を迂回できない. ポータル自体には認証・名簿・出欠の更新ロジックを置かない.
未提供のAppはURLが設定済みなら既存Appへの入口とし, 未設定なら表示しない既存案を維持. 大会参加希望と大会班の入口を分け, 利用権限に応じて表示する案.
登録状況を表示する場合は所有Appの概要APIを使う. 取得失敗は確認不能として表示し, ポータル全体や他Appへの入口を停止させない案.
操作対象会員は各Appへヒントとして渡せるが, 受け取るAppで再確認する. 直接アクセスと認証復帰は[全体設計](../../../documents/architecture.md)を参照.

## データの取得と保存

初回はポータル独自の業務・監査・ジョブ実行テーブルを作らない. アカウント・会員紐付け・ロール等のglobal情報は認証App等の公開APIから取得し, ポータルから直接SELECT・JOINしない. 入口URL・表示名等は設定で管理する. 閲覧・画面遷移の操作履歴を保存せず, バックアップや削除ジョブは所有Appの運用APIと既存のoperation_runsで扱う.
