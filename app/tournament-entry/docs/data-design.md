# 大会参加希望AppのDB設計

区分はlocal, 管理者は大会参加希望App. スキーマはtournament_entry_local. 認証・会員情報の正本はglobalに置き, 所有AppのAPIを利用する.

参加希望ID, 大会ID, 会員ID, 希望内容, 版, 操作者, 記録日時を所有する. 希望の変更・取消範囲, 日程別または級別の入力単位, 保持期限が未決.

後続リリースの業務条件を確定してから全テーブルの列名・型・NULL・既定値・入力規則・制約・保持期限を定義する. 当該Appの辞書確定前にSQLや入力フォームを作成しない. これは後続Appの着手条件であり, 未定義でも初回4Appのリリースを妨げない. 業務構造を未定義のJSON列へ格納する設計は採用しない.

連携する公開データは[大会契約](../../../contracts/tournaments.md)に記載する. global/localの管理規則は[DB設計](../../../documents/data-design.md)に従う.
