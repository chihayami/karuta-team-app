# App固有仕様

業務要件と具体的な設計案を記載する. 未確定の判断は「案」または「未決」と明示する.


## 認証・家族対応

要件:

- LINEアカウントと会員は多対多. 保護者による代理操作を可能にする.
- 初回登録後に紐付け内容をロックする.
- 管理権限の付与・剥奪, 家族紐付けの追加・解除, LINEアカウント変更に対応する.
- 正会員・准会員を対象とした利用を許可する. 操作者本人の会員種別だけでアカウント全体を利用不可にしない.
- 非会員・退会済み・メイト会員の保護者も, 正会員・准会員の子どもへの有効な紐付けがあれば代理操作できる.
- 自己申告の紐付け状況の事後確認・修正・管理権限付与を扱う専用ロールを設ける. 確認は承認ではなく, 利用開始条件にしない.
- 初回紐付けは自己申告制とし, 登録後は本人から変更できない.

提案:

- LINE認証と, 紐付いた各会員を対象としたアプリ利用可否を分ける. 保護者本人が非会員でも, 利用可能な会員への代理操作を許可する.
- 複数会員に紐付く場合は対象会員ごとに利用可否を判定する.
- 続柄は「本人」「保護者」等とし, 父・母の固定枠や性別を前提としない. 複数保護者をそれぞれ登録可能とする.
- 家族として紐付いていても, 対象会員の管理権限を継承しない.
- 自己申告の初回確定後は家族追加も管理者対応とする案. 招待コードは初回対象外.

自己申告は名簿の名前検索から選び, 1つのLINEアカウントの最大登録可能数は5名. 休会時の本人利用は原則不可. ロール付与の上限は設けない. 追加・変更の確認手順, 初期管理者の指定とメイト会員本人の操作範囲は詳細化する.
専用ロールの名称は `ACCESS_ADMIN` を提案. 名簿管理や昇級登録の権限とは分離する.
