# App固有仕様

業務要件と具体的な設計案を記載する. 未確定の判断は「案」または「未決」と明示する.

## 参加者一覧の公開

募集中の練習の参加者一覧を全員へ開示する.
「全員」はログイン済みでアプリ利用資格のある利用者とする. 未ログインでの業務情報公開は, 将来機能も含めて不要. 「募集中」は公開中かつ締切前とする案.
公開列は氏名・級・構造化した遅刻早退・自由記述の備考とする. 備考の入力欄に次の製品向け注記を常時表示する.

> この内容は、ログイン済みで利用資格のある会員全員が閲覧できます。

募集期間中の備考公開と, 保持期限後に自由記述を長期保存しない方針は両立させる. ログイン画面・認証処理に必要な入口は業務情報の未ログイン公開とは区別する.
締切後の他会員一覧と過去集計の閲覧範囲は従来の管理者限定案を残す. 募集中の開示合意から期間外への開示を自動拡張しない.

## 練習登録・変更・取消

1. 対象会員を選ぶ.
2. サーバーが有効な紐付け, 対象会員の利用資格, 練習状態, 対象級, 締切を確認する.
3. 定員を超えていても通常登録として受け付ける. 超過を理由に待機状態へ変更しない.
4. 登録・変更・取消後に人数と自分の状態を更新する.
5. 練習当日00:00以降の一般操作は拒否し, 専用メールを案内する. 管理担当者は保持期限まで訂正できる案.

遅刻・早退の入力は「なし / 時刻 / 第何試合 / その他」の区分と補足を提案する. 実出席の確認欄は設けない.
備考や補足は個人別記録として期限対象に含める. 詳細な人数集計は[練習データ設計](data-design.md#級別遅刻早退の集計)に従う.
同じ会員を複数の保護者が更新する場合, 後から古い画面の内容を上書きしないよう競合を検知して再読込を求める.

## 練習管理と例外

- 公開前の下書き, 公開, 中止を用意する案. 公開前は一般利用者に表示しない.
- 中止後は一般利用者の出欠更新を停止し, 既存登録を履歴として保持する. 中止を理由に個人別記録を無期限保存しない.
- 登録者がいる練習の開催日変更は初回では禁止し, 元練習を中止して新規作成する案. 締切・保持期限の延長や意図しない参加登録の移動を避ける.
- 登録者がいる練習の対象級変更は不適合者一覧を確認させる. 既存登録を無断で取消にしない.
- 定員は変更可能. 減らして超過しても登録を取り消さない.
- 練習時点で対象級外になった場合も取消は可能とし, 新規登録・再登録の資格はその時点で判定する案.
- 休退会に伴う未来の既存登録は名簿管理者に要対応として表示し, 練習会設定班メンバーが取消等を判断する案. 自動取消は行わない.

## 保持期限後の表示

練習の個人別記録は表示せず, 登録人数・級別人数・遅刻早退人数の集計へ切り替える.
期限経過後に新たな個人別出欠を作成する訂正は許可しない案. 個人別履歴を復元して集計をやり直す運用は設けない.
集計の訂正が必要な場合の権限と根拠は別途設計し, 初回は閲覧のみとする案.
