# App境界のテスト仕様

公開契約とApp境界を検証する. 未確定の業務条件は具体化後に期待結果を確定する.

| ID | 検証 | 期待結果案 |
| --- | --- | --- |
| <a id="bnd-sys-01"></a>BND-SYS-01 | 他App内部のimportとDB直接アクセス | 静的検査とDB権限テストで拒否. 所有Appの公開API経由だけを許可 |
| <a id="bnd-sys-02"></a>BND-SYS-02 | 名簿APIの提供側・利用側契約 | 内部スキーマ変更でも公開契約を維持. 用途別に必要最小項目のみ返す |
| <a id="bnd-sys-03"></a>BND-SYS-03 | 古いセッション・キャッシュと権限剥奪 | 次の操作を拒否. API照会と更新の競合も検証して[TST-SYS-04](specification.md#tst-sys-04)を維持 |
| <a id="bnd-sys-04"></a>BND-SYS-04 | 名簿・認証APIの停止 | 依存する更新は確定しない. 通信失敗を級不明として集計しない |
| <a id="bnd-sys-05"></a>BND-SYS-05 | 月次処理の途中失敗 | 所有App単位で再開. 必要な集計前に名簿を消さず, バックアップを含む全工程完了前に成功としない |
| <a id="bnd-sys-06"></a>BND-SYS-06 | 他Appの実装を起動せず固有テストを実行 | 公開契約スタブで実行可能. 実連携は提供側・利用側の契約試験で別途確認 |
| <a id="bnd-sys-07"></a>BND-SYS-07 | 大会2Appの越権・内部情報漏洩 | 一般会員は大会班のAPIや内部タスクを参照・更新できない |
| <a id="bnd-sys-08"></a>BND-SYS-08 | 希望受渡しの重複・不達・順序逆転 | 同じ希望と版を二重処理しない. 古い版を新しい版として上書きしない |
| <a id="bnd-sys-09"></a>BND-SYS-09 | 大会締切時の未受領希望 | 保存済み希望を照合可能. 締切・受領条件の詳細な期待結果は後続で合意 |

[BND-SYS-07](miniapp-contracts.md#bnd-sys-07)〜[BND-SYS-09](miniapp-contracts.md#bnd-sys-09)は後続リリース. [BND-SYS-01](miniapp-contracts.md#bnd-sys-01)〜[BND-SYS-06](miniapp-contracts.md#bnd-sys-06)の実装方式は先行実証と契約レビューで具体化する.

## 公開APIの追加検証

[公開契約](../../contracts/README.md)の具体化に対応する. 既存ケースの業務期待結果は維持する. 操作名・DTO等の案を本体実装前に確定し, 提供側と利用側の自動契約テストとして実装する.

| ID | 検証 | 期待結果 |
| --- | --- | --- |
| <a id="bnd-sys-10"></a>BND-SYS-10 | 初回4Appの全公開操作の入出力 | [API索引](../../contracts/README.md#提供apiの索引)の操作を提供側・利用側で検証. 必須項目・型・一覧上限・ページングを検査し, 内部列・LINE識別子・セッション生値を返さない |
| <a id="bnd-sys-11"></a>BND-SYS-11 | callerApp・actorId・用途の偽装 | ブラウザの自己申告を認証根拠にしない. 未紐付け主体は初回候補検索の許可範囲だけを利用でき, 空検索や非公開詳細取得を拒否 |
| <a id="bnd-sys-12"></a>BND-SYS-12 | 対象なし・非公開対象・級不明・依存停止 | 非公開対象の存在を漏らさず, known=falseは成功時の級不明だけに限定. 停止を不明級や空の成功一覧として扱わない |
| <a id="bnd-sys-13"></a>BND-SYS-13 | 非対応契約版・後方互換項目追加 | 非対応版はCONTRACT_UNSUPPORTED. 同じメジャーの任意項目追加でも既存利用側の契約試験が成功 |
| <a id="bnd-sys-14"></a>BND-SYS-14 | 認証と名簿の相互連携 | 初回紐付けでも主体検証が再帰せず, 認証済み文脈と用途別認可を維持. 古いaccessRevisionだけで更新を許可しない |
| <a id="bnd-sys-15"></a>BND-SYS-15 | ポータルの概要取得障害 | 確認不能を表示し, 他Appの入口を維持. 登録概要に他会員の氏名・備考を含めず, 遷移先でも対象を再認可 |
| <a id="bnd-sys-16"></a>BND-SYS-16 | 運用APIの境界・再実行 | 一般セッション・別環境の運用主体を拒否. 同じoperationIdで重複処理せず, 期限再適用前の復元を完了にしない |
| <a id="bnd-sys-17"></a>BND-SYS-17 | 大会APIの希望版・受領状態・開示範囲 | 後続実装で検証. 同一版の再送を二重受領せず, 古い版を上書きしない. 未受領・通信障害・参加確定を区別し, 内部メモ・入金タスクを返さない |
