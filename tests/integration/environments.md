# 開発版・本番版のバージョン管理テスト仕様

[環境仕様](../../documents/development-environment.md)の受入を検証する. 実行可能なアプリテストは本体実装時に追加する. 通常CIでは隔離した環境設定・保存先を用い, 実Vercelでの配信確認は運用者の設定後に行う. 本番DBへ試験データを書き込まない.

| ID | 検証 | 期待結果 |
| --- | --- | --- |
| <a id="tst-env-01"></a>TST-ENV-01 | developとmainのデプロイ設定 | developはPreview・開発接続先, mainはProduction・本番接続先. 開発更新で本番の配信版が変わらない |
| <a id="tst-env-02"></a>TST-ENV-02 | 環境設定不足・他環境の資格情報 | 不足時はビルドまたは処理を拒否. 本番へフォールバックせず, 他環境のセッション・運用資格情報を受理しない |
| <a id="tst-env-03"></a>TST-ENV-03 | 表示版とデプロイ記録 | 表示のソース版・SHA・環境が成果物と一致. 完全SHA・デプロイID・契約版・DB版・固定URLの対応を追跡可能 |
| <a id="tst-env-04"></a>TST-ENV-04 | 同一コミットの再デプロイ・設定変更 | SHAが同じでもデプロイID・設定改訂を区別. 新設定が新しい成果物へ適用され, 過去の記録を上書きしない |
| <a id="tst-env-05"></a>TST-ENV-05 | 開発確認後の本番ビルド | 対象SHAを追跡でき, 本番用設定を使用. 開発DB・LINE・GASの設定を本番成果物へ混入させない |
| <a id="tst-env-06"></a>TST-ENV-06 | 互換版への切戻しと非互換版の選択 | 互換性確認後に対象環境だけ切戻し, 固定URLと記録を更新. DB・API・設定が非互換なら自動切戻しを止め, DBを無条件復元しない |
| <a id="tst-env-07"></a>TST-ENV-07 | featureブランチ・初回Vercel設定 | 本番資格情報が個別Previewへ渡らない. 初回デプロイの実対象環境を確認し, developという名前だけで開発環境と判定しない |

既存の[TST-SYS-15](specification.md#tst-sys-15)等の環境分離試験を維持し, 版識別・配信の観点を追加する.
