# 実装着手と受入の条件

## 設計の確定条件

- 初回4Appの責務とglobal/localのテーブル所有者が明確である.
- 大会2Appの[DEC-SYS-02](open-questions.md#dec-sys-02)は後続Appの実装開始条件であり, 未定義のまま初回4Appをリリースできる.
- 初回全テーブルの列名・型・NULL・既定値・入力規則・複合制約をデータ辞書で確定する.
- [設計判断](open-questions.md)のうち対象工程に影響する未決事項を解消し, テスト期待結果と一致させる.
- 開発版は[環境仕様](development-environment.md)に従い初回から提供する. GitとVercelの版対応・本番との同時利用・切戻しを[環境テスト](../tests/integration/environments.md)で確認する.
- 各Appの[公開API](../contracts/README.md)を提供側・利用側で契約検証し, 未決の通信方式や更新時整合性を先行実証で確定する.

## 技術実証

| ID | 検証対象 | 完了条件 |
| --- | --- | --- |
| <a id="poc-sys-01"></a>POC-SYS-01 | LINE認証・利用者JWT・RLS | 偽装・越権拒否, 失効, 開発と本番の分離, 無料運用条件を確認 |
| <a id="poc-sys-02"></a>POC-SYS-02 | バックアップ・削除・復元 | 版履歴を含む全保存先で期限を守り, 公開前に期限・失効状態を適用できる |
| <a id="poc-sys-03"></a>POC-SYS-03 | 資格・紐付けと業務更新 | 公開契約を通した確認と更新の競合を扱い, 権限剥奪後の操作を拒否 |
| <a id="poc-sys-04"></a>POC-SYS-04 | 会員検索と公開項目 | 用途別の最小DTOと対象権限を検証 |
| <a id="poc-sys-05"></a>POC-SYS-05 | 期限境界と参照整理 | 名簿削除前に必要な練習集計を完了し, 他会員や保護者アカウントを巻き込まない |
| <a id="poc-sys-06"></a>POC-SYS-06 | 名簿・出欠移行 | 対応表, エラー保留, 件数・ID・級・種別・日付を照合 |
| <a id="poc-sys-07"></a>POC-SYS-07 | 性能と運用 | 合意した応答時間, 同時実行数, 復旧時間, 許容損失, 実行精度を満たす |

技術実証は最小構成と架空データで実施する. 実証結果を確認して本体実装へ進み, 結合・E2E・運用引継ぎを完了して本番切替を判断する. モックによる成功を実機確認の代わりにしない.

## 工程

対象リポジトリと既存変更の確認, 開発版基盤・認証・保存方式の実証, DB制約・入力規則の検証, 各App実装, 移行リハーサルと試験運用の順で行う. 詳細は[実装計画](implementation-plan.md)に記載する.
