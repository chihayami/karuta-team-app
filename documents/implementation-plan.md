# 実装・検証計画案

各Appの仕様, データ辞書, 公開契約に従って実装と検証を行う.

## 構成案

[全体設計](architecture.md)に従い, /workspace/app配下でAppごとに仕様・実装・テスト・DBマイグレーションを所有する. 大会参加希望と大会班は別Appとして後続開発する.
汎用UI等は共有可能. 認可・名簿参照は公開契約経由とし, 締切等の業務判定は各Appに閉じる. Supabaseは共通基盤とし, global/localのテーブルと管理責任を分ける. 開発・本番は別プロジェクトとする.
[IMP-SYS-05](implementation-plan.md#imp-sys-05)ではApp境界・DB権限・公開APIを実証し, [IMP-SYS-06](implementation-plan.md#imp-sys-06)では認証Appとポータルを別々に組み立てる. [App間契約テスト](../tests/integration/miniapp-contracts.md)を各工程の検証に含める.
依存ライブラリは着手時にサポート対象の最新安定版を公式資料で確認し, バージョンとlockfileを固定する. 現時点で具体的なバージョンは未選定.

## 移行・切替案

1. 既存名簿の列名・会員コード・種別・級・日付と取込件数を確認する. 現行システムに直接書き込まない.
2. 対応表を作り, 匿名化したサンプルで取込とエラー表示を確認する.
3. 開発環境で移行リハーサル. 件数・重複・欠損・現在級・会員種別を照合し, 勝手に補完しない.
4. 初回に移す未来の練習・既存出欠の範囲を確定する. 旧LINE紐付けを引き継げるか識別子の条件を確認する.
5. 切替日時を決め, 旧環境の更新停止と差分取込を行う手順を用意する.
6. 少人数で試験運用し, 問題があれば新規受付を止め, 旧環境へ戻す際の新規登録差分を照合する. バックアップ上書きだけで戻さない.

本番切替・GASを含むデプロイの具体的な操作は別途手順化する. Gitのpush・PR作成・マージの担当と条件は[Git運用規約](git-workflow.md)に従う. Gitのpush許可をGASデプロイの実行指示とは扱わない.

## 外部設定と残る技術検証

- LINEチャネル・LIFF ID, 管理用アカウント, 専用連絡メールの設定が必要. 秘密情報は文書へ貼り付けない.
- 無料枠の団体利用可否, 容量, 定期処理, 稼働停止条件を実装前に公式資料と対象設定で確認する.
- 認証用JWT方式の無料枠対応と鍵運用を[IMP-SYS-04](implementation-plan.md#imp-sys-04)で確定する.
- GAS・スプレッドシートの保存先では履歴・複製も含めた削除可能範囲を確認する. 復元可能性と保持期限の両立を確認できるまで方式を確定しない.
- バックアップは24時間間隔・15日保存, 確認担当者は全体管理者. 復旧時間と実行精度は未決.
- 自動通知は初回対象外案. バックアップ等の失敗は運用画面で確認可能にし, 外部通知の有無は別途決定する.

毎月1日の共通処理は月次削除をまとめ, 日次バックアップ等の期限を遅らせない. アカウント利用終了判定・定期削除は行わない. 正確な実行時刻等の運用詳細は別途確定する.
