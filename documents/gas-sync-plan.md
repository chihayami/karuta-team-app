# GAS同期基盤の実装計画

## 状態と範囲

2026-10-11にユーザーが承認した計画. 作成済みの開発GASとリポジトリのコードを紐付け, 設定確認まで行える最小基盤を用意する.
現在のブランチは `feature/mil-sys-02-foundation`. 作業開始時の変更は設定手順書とその索引であり, 既存変更を保持して追記する. `web/.env.local` の利用者設定も保持する.
本計画では同期の準備と設定確認を対象にする. 保存・削除・復元の業務処理は[IMP-SYS-03](implementation-plan.md#imp-sys-03)の別計画で, DEC-OPS-01・DEC-OPS-02と保存方式をレビューしてから実装する.

## 対象ファイルと実装

- `gas/backup/` にGAS専用のソースと `appsscript.json` を置く. V8とAsia/Tokyoを指定し, 取得した既存manifestのDrive advanced service等を確認して必要な設定を引き継ぐ.
- `gas/backup/src/config.js` にスクリプトプロパティ `APP_ENVIRONMENT`, `BACKUP_FOLDER_ID` の検証を置く. 最初の実証はdevelopmentのみ. 未設定や本番環境指定を拒否し, 値をエラーへ出さない.
- `gas/backup/src/healthcheck.js` にGASエディタから実行できる設定確認関数を置く. 成功・環境・フォルダID設定の有無だけを返し, 実際のID・資格情報・プロパティ全体を返さない. 設定文字列の確認であり, Driveフォルダの存在や接続成功の確認とは区別する.
- `gas/backup/.claspignore` で送信対象をGAS用ソースとmanifestへ限定する. `.clasp.json` は運用者が作成済みの開発Script IDを指定して管理し, Git対象にしない.
- GAS用のlintとローカル自動テストを追加する. Node.jsのvm等で必要なGASオブジェクトを置き換え, 正常系・設定不足・本番指定拒否・値の非露出を検証する.
- `package.json` にローカル検査と送信対象確認のコマンドを追加する. claspは3.4.1の一時実行を使用し, 認証・clone・pushの操作を明示する. 既存のWeb検査・commit hookを維持する.
- [GAS設定とコード同期の手順](gas-development.md)を実装後のコマンド名・関数名と一致させる.

GASソースはブラウザやNext.jsのコードからimportしない. GASは単独の実行環境であり, Webの `.env.local` を読み込まない.
実設定の読込, Google認証, remote sourceの取得・更新は運用者の操作とし, ここまでの承認だけでAIから外部プロジェクトへpushしない.
既存のGoogle側ソースに独自の処理がある場合は, 取得内容を確認し, 無断で置き換えず実装範囲を相談する.

## 検証

- GAS設定検証と設定確認関数の自動テストを追加する. 他Appの未決業務仕様をテストで確定しない.
- Node.js 24で型チェック・lint・対象テスト・既存Webテスト・ビルドを実行する. GASではGAS環境の型・global APIと送信ファイルの整合性を確認する.
- 文書の整形・ID・リンク・差分検査を実行する. テスト仕様の既存期待結果は変更しない.
- ローカルで確認できるのはGASコードの振る舞いと送信対象. 実GASへの同期とエディタからの実行は, 運用者の対象確認・認証・反映後に結果を記録する.

## 完了条件

1. ローカルにGAS用ソース・manifest・送信対象制限が揃い, 検査が通る.
2. Script ID・folder ID・Deployment IDの用途と設定先が明確である.
3. 運用者が開発用GASへコードを送信し, エディタから設定確認関数を実行できる.
4. 同期確認と, バックアップ・DB接続・保存期限適用の実証を区別して報告する.

Web appとしての公開, 定期トリガーの登録, Supabaseへの通信, 実データの保存・削除はこの計画に含めない. これらの実装・実行条件は保存・復元の計画で具体化する.

## 実装と検証結果

- GAS用ソース・manifest・clasp設定例・送信対象制限を `gas/backup/` に追加した. 設定確認関数は `checkDevelopmentSetup`.
- `APP_ENVIRONMENT` と `BACKUP_FOLDER_ID` だけを読み込み, development以外・未設定・空白を含むIDを拒否する. エラーと成功ログへ設定値を出さない.
- GAS用型定義を追加し, WebとGASの型検査を分離した. Node.js 24で型チェック・lint・GASテスト29件・既存Webテスト82件・既存ツールテスト12件が成功した.
- 同期基盤の実装時点では, `gas:check-files` でclaspの実際のローカルファイル選定を検査した. 認証・リモート更新なしでmanifestと2つのソースだけが対象になることを確認した. 後続の保存実証で追加した送信対象は[GAS手順](gas-development.md)を参照.
- Webビルドは隔離した架空設定で成功した. 利用者の `.env.local` へ書き込まず, 検証前後でファイルが同一であることを確認した.
- WebのHTTP検査も成功した. 文書整形・IDとリンクの整合性・差分検査が成功した.
- プロジェクト依存の `npm audit` は指摘0件. 一時実行するclaspの依存はこの検査の対象に含まれない.
- security-review skillの観点で設定と出力・送信境界を確認した. 現在の実装では他のプロパティを一括読込せず, 設定値をエラーやログへ返さず, Web app・定期トリガー・DBアクセスも追加しないことを確認した. この範囲で要修正の指摘なし. 実GASの権限・OAuth・既存コードの検証は未実施.
- 2026-10-11に運用者からGAS設定完了の報告を受けた. 同期と設定確認は運用者による完了報告として記録する. AIからGoogle側へ接続しての再確認は行っていない.
- Driveフォルダへの保存・読戻し, DB接続, 保存期限適用・復元は未実施. 次のレビュー対象は[保存先の入出力実証計画](gas-storage-probe-plan.md).
