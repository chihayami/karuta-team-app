# Git運用規約

ブランチと環境の対応は[環境仕様](development-environment.md#gitとvercelの環境対応)を正本とし, 本書は変更を反映する手順を定める. AIのGit操作制限は[AGENTS.md](../AGENTS.md)に従う.

## ブランチ

| ブランチ         | 用途                     | 分岐元       | 反映先                          |
| ---------------- | ------------------------ | ------------ | ------------------------------- |
| `main`           | 本番へ反映する履歴       | 継続ブランチ | 本番環境                        |
| `develop`        | 継続開発と開発版の検証   | 初回は`main` | 検証後に`main`                  |
| `feature/<内容>` | 新機能                   | `develop`    | `develop`                       |
| `fix/<内容>`     | 通常の不具合修正         | `develop`    | `develop`                       |
| `docs/<内容>`    | 文書変更                 | `develop`    | `develop`                       |
| `chore/<内容>`   | 設定, 依存更新, 開発補助 | `develop`    | `develop`                       |
| `hotfix/<内容>`  | 本番の緊急修正           | `main`       | `main`, その後`develop`にも反映 |

内容は短い英小文字・数字・ハイフンで表す. 例: `feature/practice-attendance`, `docs/development-conventions`. 必要なら課題番号を含める. 個人名, 会員情報, 秘密値をブランチ名に含めない. 1ブランチを1つの目的に対応させ, マージ済みブランチを別目的で再利用しない.

AIは表に示す `feature/`, `fix/`, `docs/`, `chore/`, `hotfix/` の作業ブランチを作成・切替できる. 表の分岐元に対応するローカルブランチがあることを確認し, そこから作業ブランチを作成する. `main`・`develop` の作成・切替, リモート設定・同期, ブランチ削除は人間が行う. indexまたは作業ツリーに変更がある場合は保持できることを確認し, 競合・上書き・変更消失のおそれがあるときは操作せず人間に相談する.

`main` と `develop` への直接コミットを禁止し, PRを経由する. force pushは禁止する. Gitタグ・Releaseは作成しない. ブランチ保護と必須チェックはリモートの運用開始時に人間が設定し, 設定が済むまでは運用手順でも同じ条件を守る.

## 通常変更と本番反映

1. 人間がリモートとの同期状態と作業ツリーを確認する. AIはローカルの `develop` から規約に沿って作業ブランチを作成・切替する. 既存変更を失わせる操作を行わない.
2. 計画レビュー後に実装し, [開発規約](development-conventions.md#検証と完了条件)の検査を行う.
3. 人間またはAIが変更をpushして `develop` 向けPRを用意する. AIのpushは `/git-push` スキル経由に限定する. 人間がレビューと必須検査の通過, 未解決の指摘がないことを確認してマージする.
4. 開発版で対象のソース版と接続先を確認し, 実機検証を含む受入結果を記録する.
5. 本番反映時に `develop` から `main` へのPRを作成し, 含まれる全変更と検証結果をレビューする. 未承認の変更が混在している場合は反映しない.
6. 人間が本番反映を行い, [環境仕様の更新手順](development-environment.md#更新切戻し手順)に従って確認・記録する. `main` へのマージが自動デプロイを起動する構成では, マージ自体を本番公開操作として扱う.

マージ方式は原則としてマージコミットとし, 継続ブランチ間の履歴の関係を保持する. 競合解消後の最終的な変更内容に対して再検証する. 履歴を書き換えるrebaseをAIに実行させない.

## 緊急修正

AIは `main` から `hotfix/<内容>` を作成・切替できる. 緊急性があっても計画レビュー, 関連テスト, 人間のレビュー, 本番反映条件を省略しない. 修正を最小限にし, 通常開発の未公開機能を混ぜない.

`hotfix` から `main` へのPRを反映後, `main` から `develop` への同期PRで修正を戻す. 競合を解消して関連テストを再実行し, 同期が完了するまで緊急修正の作業を完了扱いにしない. その後の通常リリースで修正が失われないことを確認する.

## 操作の担当と履歴の扱い

| 操作                                                             | 担当・条件                                                                             |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 状態確認・差分確認                                               | AIも実行可能                                                                           |
| 作業ファイルの編集・検査                                         | 承認済み計画の範囲でAIも実行可能                                                       |
| 作業ブランチの作成・切替                                         | AIは表の分岐元と作業状態を確認したうえで実施可能                                       |
| `main`・`develop` の作成・切替, リモート設定・同期, ブランチ削除 | 人間が実施                                                                             |
| ステージング                                                     | AIは `/commit`・`/git-push` スキルの手順に従う場合のみ実行可能. 独立して一括追加しない |
| ローカルコミット                                                 | AIは `/commit` スキル経由のみ. `/git-push` からの委譲も同スキルの手順に従う            |
| push                                                             | AIは `/git-push` スキル経由のみ. 対象と宛先の確認・承認はスキルの手順に従う            |
| PR作成                                                           | AIも実行可能. 対象ブランチ, 差分, 検証結果を確認して作成する                           |
| マージ                                                           | ローカルマージ・PRマージとも人間が実施. AIによる自動マージの設定も禁止                 |

AIはstash, discard, 履歴の巻戻しや書換えで状態を自動修復しない. 問題がある場合は現状と必要な対応を報告する. コミットは目的ごとに分け, `/commit` の日本語メッセージ形式に従う. ローカルコミットがあることをpush済み・公開済みと扱わない.

AIは `/git-push` スキルを介して作業ブランチをpushし, PRを作成できる. この許可を `main`・`develop` への直接反映やマージの許可と扱わない. PR作成後は人間のレビューとマージに引き継ぎ, マージコマンドや自動マージ設定で反映しない.

## 現行状態からの移行

本規約作成時点の作業ブランチは `main` である. 移行時は人間が既存のローカルコミットと作業ツリーを確認し, `develop` とリモート設定を用意する. 以降, AIは本書で定める作業ブランチを作成・切替できる. 既存履歴を自動で書き換えたり, 未確認のローカルコミットを無条件にpushしたりしない.
