# 大会参加希望Appと大会班Appの連携案

大会参加希望と大会班は別Appとする. 以下のデータ所有・受渡方式は後続リリースでレビューする提案. 両者のlocalテーブル・内部モジュール・画面状態を分離する.

| 正本の所有者 | データ                                           | 他Appへの提供                                   |
| ------------ | ------------------------------------------------ | ----------------------------------------------- |
| 大会班       | 大会ID, 日程, 募集条件・締切と版                 | 参加希望Appへ会員向け募集情報だけを提供         |
| 大会参加希望 | 希望ID, 対象会員ID, 大会ID, 希望内容・変更版     | 大会班へ権限付きAPIで受け渡す                   |
| 大会班       | 受領した希望の版, 処理状態, 確定名簿, 作業タスク | 参加希望Appへ当該会員に開示可能な結果だけを提供 |

参加希望の保存完了と大会班側の受領・参加確定は別の事実とする案. 大会班の業務記録から参加希望の原文を直接書き換えない. 希望変更・取消と班による訂正の責任範囲は後続で確定する.
受渡しには希望IDと版等の冪等キーを用い, 再送を重複受付にしない案. 不達・遅延時は未受領として再試行し, 成功と表示しない. 同期APIかイベントか, 締切時のスナップショット取得方式は未決.
班の受付名簿に必要なスナップショットは用途を限定し, 希望の正本とは区別する. 希望Appから班の内部メモ・入金タスク等を取得できないようDTOを分離する. 班Appへの直接URL・API操作には班の権限を要求する.

## 後続で確定する事項

- 会〆翌日07:00の既存ルールを募集条件APIで一貫させる方法. 締切ちょうどの扱い, 変更・取消可能期間.
- 募集条件の更新と希望送信が競合した場合の版チェック・再確認.
- 締切時に保存済みで受渡し待ちの希望をどの工程で取り込むか. 取りこぼしを検出する照合方法.
- 班の訂正を会員にどう表示し, 希望変更と競合した場合にどう解決するか.
- 代理入力の範囲, 公開する結果項目, 参加希望・受付スナップショット・確定名簿の保持期限.
- 会計Appとの境界. 送金実施は従来どおりスコープ外.

これらの未決判断を既存の大会業務ルールから自動補完しない. [大会班の業務ルール](../app/tournament-operations/docs/business-rules.md)の合意事項は維持する.

## APIへの対応

希望の取得は[参加希望API](tournament-entry.md), 募集情報・受領・開示結果は[大会班API](tournament-operations.md)に定義する. 共通のエラー・契約版・呼出文脈は[公開契約](README.md)に従う. 本書の未決事項を確定済みとは扱わない.
