# App間の公開APIと連携

本書とApp別契約は実装予定の公開境界を定義する. APIは未実装. 操作名・DTOは契約案であり, 通信方式・実際のURL・型定義は先行実証で確定する. 既存の業務上の未決事項は各App仕様に従いレビューする.

## 提供APIの索引

| 提供App | 公開操作 | 利用元 | 正本 |
| --- | --- | --- | --- |
| 認証 | 主体確認, 現行権限・代理対象確認 | 全App | [認証API](auth.md) |
| ポータル | 利用可能な入口一覧 | ポータル画面. 他Appは入口URLだけを利用可能 | [ポータルAPI](portal.md) |
| 名簿 | 現役検索, 初回紐付け候補, 基本情報, 指定日時点の級 | 認証, 練習, 大会2App | [名簿API](roster.md) |
| 練習 | 練習一覧・参加人数, 対象会員の登録概要 | 練習画面, 必要な場合のみポータル | [練習API](practice.md) |
| 大会参加希望 | 参加希望と版の取得 | 大会班 | [参加希望API](tournament-entry.md) |
| 大会班 | 募集情報, 希望受領, 会員向け処理結果 | 大会参加希望 | [大会班API](tournament-operations.md) |

一般画面からの登録・編集は各所有Appの仕様と認可に従う. 本索引はApp間で利用可能なAPIを示し, 私有テーブルや管理用CRUDを他Appへ一括公開するものではない. 大会関連は後続リリースの案である.

## 呼出しと共通DTO

初回は同一Webアプリ内のサーバー側公開インターフェイス経由の呼出しを基本案とする. ブラウザは所有Appのサーバー入口を呼び, サーバーが主体を検証する. HTTP分離が必要になった場合は同じ契約をアダプターへ写像し, HTTPS・サービス認証・タイムアウトを実装前に定める. 以下の操作名はHTTPエンドポイントの実在を意味しない.

| 項目 | 契約案 |
| --- | --- |
| 呼出文脈 | `actorId`, `callerApp`, `environment`, `requestId`, `contractVersion`. actorIdは検証済み内部アカウントID. callerAppはサーバーが識別し, ブラウザの自己申告を信用しない |
| 主体検証 | セッションまたは運用資格情報を入口で検証. 別環境の資格情報・宛先を拒否. アカウント状態, 現行ロール・紐付け, 開発版検証者の許可を操作時に確認 |
| ID・版 | 業務IDは既存データ辞書の型. `revision`は比較用の不透明な文字列で, DB列の存在を仮定しない. API契約版, データ版, デプロイ版を区別する |
| 日付 | 業務日は`YYYY-MM-DD`, 時点はタイムゾーン付きISO 8601. 練習の締切はAsia/Tokyo. 大会の未決条件を流用しない |
| 一覧 | `items`, `nextCursor`を返す. `limit`は1〜100, 既定20の案. カーソルは用途・条件・主体に束縛し, 認可の代わりにしない |
| 成功 | `{ data, meta: { requestId, contractVersion } }`. 必要な操作のみdataにrevisionを含む |
| 失敗 | `{ error: { code, retryable }, meta: { requestId, contractVersion } }`. スタック, SQL, LINE識別子, セッション生値を返さない |

用途は操作ごとに固定し, 呼出元が任意の用途や権限名で情報範囲を拡大できないようにする. DTOは明示した項目のみ返す. サービス認証だけでは利用者の業務権限を代替しない. 非公開対象の存在が漏れる場合, 外向けには権限不足を対象なしと同じ応答にする.

## エラー・再送・整合性

| code | 意味 | HTTPへ写像する場合の案 | 呼出側の扱い |
| --- | --- | --- | --- |
| UNAUTHENTICATED | 未認証・失効 | 401 | 認証へ戻り, 元の操作は再確認 |
| FORBIDDEN | 権限・資格・環境不一致 | 403 | 拒否. 別環境へ自動フォールバックしない |
| NOT_FOUND | 対象なし, または非公開対象 | 404 | 空の成功データと区別 |
| INVALID_INPUT | 型・値・検索条件不正 | 400 | 入力修正 |
| CONFLICT | データ版・条件の競合 | 409 | 現行版を取得し, 利用者に再確認 |
| CONTRACT_UNSUPPORTED | 契約版非対応 | 400 | 移行が必要. 別版へ暗黙変換しない |
| RATE_LIMITED | 呼出頻度制限 | 429 | 指定された待機時間以降に再試行 |
| DEPENDENCY_UNAVAILABLE | 必要な依存の停止・タイムアウト | 503 | 業務更新を確定せず, 確認不能として扱う |

更新の自動再送は所有Appが冪等性を保証する操作に限定する. 対象・版・操作・主体・環境に結び付けたキーを使用し, 同じキーで異なる内容が来たらCONFLICT. タイムアウトは更新失敗確定とはみなさず, 処理結果を照会する. 認可失敗・入力不正は自動再送しない.

事前照会のrevisionだけでは更新時の整合性を保証できない. [POC-SYS-03](../documents/specification-review.md#poc-sys-03)で公開境界を保った原子的検証または版付き検証の確定手順を実証する. 成立するまで業務更新の方式を確定しない. 表示用キャッシュを認可に使わない.

## 連携手順

1. ログイン・初回紐付け: 認証AppがLINE認証を検証 → [主体確認](auth.md#api-aut-01) → [候補検索](roster.md#api-rst-02) → 選択会員の存在・現行状態を確認 → 認証App内で紐付けを確定・ロック. 主体確認から名簿へ再帰呼出ししない.
2. ポータル: 主体・対象会員確認 → [入口一覧](portal.md#api-ptl-01) → 必要な場合だけ[練習登録概要](practice.md#api-prc-02). 概要取得失敗でも他Appへの入口を維持し, 遷移先で再認可する.
3. 練習登録: 認証APIで操作者と対象の関係を確認 → 名簿APIで現行資格を確認 → 練習Appが締切等を判定 → 競合対策を含む更新と監査を自Appで確定. 操作者と代理対象を別々に扱う.
4. 練習集計: 練習Appが登録を取得 → 名簿の[指定日時点の級](roster.md#api-rst-04)を照会 → 練習Appが集計を保存. 通信失敗を不明級へ変換しない. 削除順序は[保存期限](../documents/data-retention.md)に従う.
5. 大会: [募集情報](tournament-operations.md#api-top-01)を取得 → 参加希望Appが希望と条件版を保存 → 大会班が希望を取得して[受領](tournament-operations.md#api-top-02) → 参加希望Appが[開示結果](tournament-operations.md#api-top-03)を取得. 同期・非同期の選択と締切競合は[大会契約](tournaments.md)で後続レビューする.

## 運用API

バックアップ・保持期限・復元は認証, 名簿, 練習および後続のデータ所有Appが提供する運用境界を経由する. ポータルは独自の運用API・テーブルを持たない. 共通操作案は`exportSnapshot`, `applyRetention`, `restoreSnapshot`, `getOperationStatus`. 入力は検証済み運用主体, 環境, `operationId`, 対象時点, 必要な保存物参照. 応答は進捗, 件数, 完了状態とエラーで, 生の個人情報を運用画面へ返さない.

一般利用者の資格情報では呼べず, 所有App・対象環境・用途を限定した権限を要求する. 同じoperationIdの再実行は重複処理しない. 保存物は保護された保存先へ渡し, 公開URLにしない. 復元完了には期限・失効の再適用を含む. 全体進捗と各Appの確定を区別し, 詳細な形式・資格情報・再開方法は[保存の技術実証](../documents/specification-review.md#poc-sys-02)で確定する.

## 契約の版管理

初回の契約メジャー版は`v1`案. 後方互換の任意項目追加は同じメジャー版で行い, 必須化・削除・意味変更は新しいメジャー版とする. 利用App一覧, 提供側・利用側の契約試験, 併存期間, 切替・撤去条件をレビューする. 開発・本番ごとに対応契約版を[デプロイ記録](../documents/development-environment.md#バージョンの識別と記録)へ記録する. 個人情報複製には用途・保存期限・訂正削除の伝播を定義し, 未定義なら複製を追加しない.

検証は[App境界のテスト仕様](../tests/integration/miniapp-contracts.md)を参照する.
